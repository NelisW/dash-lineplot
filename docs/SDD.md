# dash-lineplot Software Design Description

Markdown flavour: LaTeX-conversion-safe (ASCII only, LF line endings),
with Pandoc/Puppeteer PDF front matter.

## Orientation

This document describes how `dash-lineplot` is built: its components, the
data that flows between them, the run-time sequence, and the design rules
the code holds to. It describes the code as it stands; for how to use the
tool, see `docs/userguide.md`, and for open defects and planned work, see
`suggestedwork.md`.

Source references are given as function names, which are stable. The code
map at the end of this document gives the line range of each function in
`dash-lineplot.py` as of 2026-10-07; those numbers drift as the file is
edited, the names do not.

## Purpose and scope

`dash-lineplot` plots time-series data in a web browser. A configuration
file names the data files, the columns to plot, and how the graphs are
grouped onto tabs; the tool reads the data, builds one Plotly figure per
graph, and serves the page from a local Flask server through Dash.

The tool is general-purpose. It knows nothing about any calling project's
directory layout, telemetry fields, sample rates or time bases. The bridge
between a project's data and the viewer is a configuration file, either
written by hand or generated by `tools/config_from_run.py`.

In scope:

- Reading CSV/space/tab-separated text, the first sheet of an `.xlsx`
  workbook, and JSON (single record array, or named groups at different
  sample rates).
- Reading the configuration from an `.xlsx` workbook or an equivalent JSON
  file.
- Serving an interactive page: tabs, linked hover, shared x range per tab,
  typed axis ranges, click and selection readouts.
- Optionally writing each figure to a standalone HTML file.

Out of scope, by design:

- Merging, aligning or resampling tables. Each table is drawn at its own
  sample rate.
- Any desktop window. The page is served to the system browser.
- Matlab `.mat` input (removed).

## Design rules

These rules shape most of the decisions below and are not to be relaxed
without a deliberate decision.

| Rule | Consequence in the design |
|---|---|
| Never merge or resample tables. | Each data file, and each group of a multi-rate JSON file, becomes its own `DataFrame`. A tab may mix traces from several tables; each trace keeps its own x samples. |
| Never interpolate a value shown to the reader. | Cross-graph readouts report the nearest recorded sample (`nearestSample`). |
| Scale and Offset are display-only. | Every numeric trace carries its true x and y in `customdata`; hover, click and selection readouts read `customdata`, never the plotted `y`. |
| Nothing about the data is inferred from a caller's conventions. | Column names, the x column and JSON groups are all named in the configuration. The only inference is that a non-numeric, non-boolean column is an enumeration. |
| Cross-platform (Linux and Windows). | `pathlib.Path` throughout; no drive letters or home directories; `environment.yml` pins version floors only. |

## Context

```text
 configuration (.xlsx | .json)      data files (.csv/.txt | .xlsx | .json)
            |                                   |
            v                                   v
   +--------------------------------------------------------+
   |  dash-lineplot.py  (one Python process)                |
   |    config loader -> data loader -> graph builder       |
   |    -> page builder -> Dash app + callbacks (thread)    |
   +--------------------------------------------------------+
            |  HTTP on 127.0.0.1:<port>          | optional
            v                                    v
   system browser: Dash renderer, Plotly.js,   ./graphs/*.html
   assets/graphsync.js, assets/*.css
```

The process serves one page, built once at start-up from one
configuration. Several processes may run at once, each on its own port
(see Port selection).

## Component overview

| Component | Location | Responsibility |
|---|---|---|
| CLI entry point | `dash-lineplot.py`, `if __name__ == "__main__"` block | Parse `--configfile`, `--port`, `--datadir`; choose a free port; start the plotter; keep the main thread alive. |
| Configuration reader | `readConfigTables`, `readPageTitle`, `DashLinePlot.loadConfig` | Read either config format into one table shape; label rows by graph set and trace. |
| Block resolver | `resolveSetContexts` | Work out which data file, x column, x label/format/scale/offset and height apply to each graph on a sheet. |
| Data loader | `DashLinePlot.loadData`, `readdatafile`, `readJsonData`, `splitDataRef` | Load every referenced data file once, into `self.datafiles`. |
| Graph builder | `DashLinePlot.makeGraphSet` | Build the Plotly figure dicts and the HTML rows (graph plus readout column) for one tab. |
| Page builder | `DashLinePlot.prepareGraphs`, `DashLinePlot.makePage` | Build every included tab and the top-level `dcc.Tabs` layout. |
| Server and callbacks | `DashLinePlot.runDash`, `DashLinePlot.setupCallbacks` | Create the Dash app, register callbacks, run the Flask server. |
| Readout helpers | `commonClickMessage`, `commonSelectMessage`, `selectionBounds`, `nearestSample`, `traceYExtent` | Format click and selection readouts from true values. |
| Port selection | `freePort` | Find a verified free port at or above the requested one. |
| Browser-side sync | `assets/graphsync.js` | Page-wide hover sync; shared x range across a `commonX` tab. |
| Styling | `assets/bWLwgP.css`, `assets/density.css` | Base grid and typography; compact/comfortable spacing. |
| Config generator | `tools/config_from_run.py` | Write a first-pass JSON configuration for a directory of JSON telemetry. |
| Config converter | `tools/xlsx_config_to_json.py` | Convert an `.xlsx` configuration to the equivalent JSON. |

## Run-time sequence

1. The CLI parses its arguments and calls `readPageTitle`, which reads the
   configuration's `header` table for `Pagetitle`.
1. `freePort(args.port)` returns the first verified free port at or above
   the requested one. If it differs, the CLI prints a notice.
1. `DashLinePlot.runPlotter` runs, in order:
    1. `loadConfig`: reads the configuration into the module-level
       `dfPlotterHeader` and `dfPlotterConfig`, and sets `pageDensity`.
    1. `loadData`: loads every referenced data file. If any is missing it
       returns `False`, nothing further is built, and the CLI exits with
       status 1.
    1. `prepareGraphs`: calls `makeGraphSet` for each included tab, filling
       the module-level `divSets`, `graphList` and `graphTabs`.
    1. `makePage`: builds the `dcc.Tabs` layout.
    1. Starts `runDash` in a daemon thread. `runDash` creates the Dash app
       (module-level `dashApp`), registers callbacks through
       `setupCallbacks`, and calls `dashApp.run(debug=False,
       use_reloader=False)`.
1. The main thread prints the URL and blocks on `threading.Event().wait()`
   until Ctrl+C.

`runPlotter` also accepts `flaskServerRunning=True`, in which case it
replaces `dashApp.layout` instead of starting a second server. This is the
module-use path; the CLI does not use it.

## Configuration

### Table shape

A configuration is a `header` table of `Variable`/`Value` pairs plus any
number of graph sheets, each becoming one tab. Only sheets whose name
contains `graph` are read as graph sheets; the tab label is the text
between the first and second `-` of the sheet name (`graph-Attitude`
gives `Attitude`).

`readConfigTables` returns the same shape for both formats:

- `.xlsx`: the `header` sheet via `pandas.read_excel`; graph sheets in the
  workbook's own order, taken from `openpyxl` because pandas does not
  guarantee it.
- `.json`: a top-level object with `header` (an object of variable to
  value) and `sheets` (an object of sheet name to a list of row objects).
  A missing `header` or `sheets` key raises a `ValueError` that names the
  missing key.

Every graph sheet is reindexed onto `CONFIG_COLUMNS` (`Variable`, `Value`,
`Format`, `LineLabel`, `GraphType`, `Scale`, `Offset`, `Colour`,
`Linewidth`, `Dash`, `Mode`, `MarkerOpacity`, `Categories`, `Datafile`),
so a column a JSON configuration omits still exists as NaN. Extra columns
are preserved.

### Row labelling

`loadConfig` concatenates every sheet into one frame, `dfPlotterConfig`,
adding a `Graph` column (sheet name) and an `Index` label per row:

| Row variable | Index label | Meaning |
|---|---|---|
| `Title` | `Title#NNN` | Opens graph set `NNN` (zero-based, three digits) on this sheet. |
| `yLabel` | `yLabel#NNN` | y-axis label and hover format of set `NNN`; resets the trace counter. |
| `yValue` | `yValue#NNN-MMM` | Trace `MMM` of set `NNN`. |
| anything else | the variable name | Sheet-level settings such as `Height`, `Datafile`, `commonX`, `ToDisk`, `Include`, `GraphTop`, `GraphBottom`. |

Downstream code recovers the set and trace numbers by splitting these
labels on `#` and `-`. A `Datafile` value of `master` is replaced by the
header's `Datafile`.

### Blocks

`resolveSetContexts` walks one sheet top to bottom. `Height`, `Datafile`,
`xLabel` and `xValue` rows update a running context; each `Title` row
snapshots it for the graph set it opens. One sheet can therefore carry
several data files, each with its own x column, scale and offset. A
`yValue` row's own `Datafile` cell overrides the block's data file for that
trace only.

The context holds `datafile`, `xvalue`, `xlabel`, `xformat` (default
`.4f`), `xscale` (default 1.0), `xoffset` (default 0.0) and `height`
(default 300).

### Header variables read by the code

| Variable | Use |
|---|---|
| `Pagetitle` | Browser tab title. |
| `Datafile` | Substituted wherever a sheet or row says `master`. |
| `Density` | `compact` (default) or `comfortable`; anything else prints a warning and uses `compact`. |
| `PageTop`, `PageBottom` | Markdown above and below each tab's graphs; `PageBottom` is prefixed with the date of the run. |

### Cell parsing

`cellFloat`, `cellText` and `cellFlag` read spreadsheet cells tolerantly:
blank, NaN and unparseable values fall back to a caller-supplied default
instead of raising. `cellFlag` accepts `true/false`, `1/0`, `yes/no`,
`y/n`, `t/f`, case-insensitively.

## Data loading

### File set

`loadData` gathers every distinct `Datafile` value from the sheet-level
rows and from the per-row `Datafile` column, then loads each one exactly
once. `self.datafiles` is a dictionary keyed by the reference string
exactly as written in the configuration, `#group` fragment included, so
two groups of one JSON file are two entries.

A relative file part is resolved against `--datadir` when one is given,
otherwise against the working directory.

### Format dispatch

Dispatch is on the lower-cased file extension:

| Extension contains | Reader | Notes |
|---|---|---|
| `xls` | `pandas.read_excel` | First sheet only; top row is column names. |
| `json` | `readJsonData` | See below. |
| anything else | `readdatafile` | Comma, tab or whitespace separated text. |

`readdatafile` handles an optional Matlab-style header: leading lines that
start with `%` are skipped, and the first of them, with the `%` removed,
supplies the column names. Without a `%` line, the first line is the
header. Separators are the regular expression `,|\t|\s+` (pandas' Python
engine).

`readJsonData` accepts two shapes, declared by the file's own structure:

- Top-level list: one record array, one table. Naming a group for it is an
  error.
- Top-level object: named groups, each a record array with its own time
  column. A group must be named with `file.json#group`; a missing or
  unknown group is an error that lists the groups present.

A missing file is reported on stdout and makes `loadData` return `False`.

## Graph construction

`makeGraphSet` builds one tab. For each `yValue` row it creates one trace;
for each `Title` row it assembles the traces of that set into one figure.

### Traces

For each trace:

- The data frame is the block's file, or the row's own `Datafile`
  override. A reference that was not loaded, an x column or a y column
  that does not exist, all raise a `ValueError` naming the sheet, the row
  and what was available.
- Plotted x is `raw_x * xscale + xoffset`.
- A numeric y column is plotted as `raw_y * Scale + Offset`. Its
  `customdata` is the pair `[raw_x, raw_y]`, and its hover template shows
  `customdata[1]` in the set's y format, so the tooltip shows the recorded
  value.
- An enumeration column (`isEnumSeries`: neither numeric nor boolean) is
  mapped to integer codes. The category order is the declared
  `Categories` list (JSON list or comma-separated text) if given, else
  order of first appearance; values in the data but missing from a
  declared list are appended, never dropped (`enumCategories`). Scale and
  Offset are not applied. The line shape is `hv` (a state holds, then
  jumps), the hover text is the state name, and `customdata` is `raw_x`.
- `Linewidth`, `Colour`, `Dash`, `GraphType`, `Mode`, `MarkerOpacity` and
  `LineLabel` are copied onto the trace when set. `Mode` defaults to
  `lines`.

### Figures

For each graph set:

- The y axis carries the set's `yLabel` and hover format (default `.4f`).
  If any trace is an enumeration, the axis ticks are replaced by the
  union of the set's category names.
- Axis titles are written as `{'text': ...}`. Plotly.js 4 renders a bare
  string title as nothing.
- The legend is anchored inside the top-right corner of the plot area, so
  every stacked graph has the same plot width and their x axes line up.
- `hovermode` is `x`; `clickmode` is `event+select`.
- In compact density the margins are cut to 60/20/8/38 px (l/r/t/b) and
  the title is drawn inside the plot area.
- The graph's CSS height is the block's `Height` with a `px` suffix. A
  bare number is invalid CSS, and Plotly would silently fall back to
  450 px.

The graph id is the sheet name followed by the set number, for example
`graph-Attitude000`. The ids of a tab are returned to the caller and
recorded in `graphList`.

### Page rows

Each graph occupies one row: the graph in a `nine columns` div, and a
`three columns` readout column built by `generateFeedbackBoxes`. That
column holds the X/Y range text inputs with Apply and Reset buttons, the
Click Data box, and, only when some trace has markers, the Rectangle Tool
Selection Data box. The range inputs' placeholders show the data extent
(`traceYExtent` for y).

On a `commonX` tab the row also carries the class `common-x`, which is
what `graphsync.js` keys on, and every graph id of the tab is recorded in
`self.commonXGroups`.

Each tab also gets the header's `PageTop`, the sheet's `GraphTop` and
`GraphBottom`, the header's `PageBottom`, and the logo image from
`icons/logoSet2long.png`, embedded as base64.

### Export to disk

When a tab's export flag is on, `graphToDisk` writes each figure to
`./graphs/<sheet>#<set>.html` through `plotly.offline.plot`. The
`./graphs` directory is created if missing.

## Page and server

### Tabs

`makePage` builds a `dcc.Tabs` component with one `dcc.Tab` per included
sheet, plus an empty `tabs-content` div, inside a div of class
`density-compact` or `density-comfortable`. With callbacks enabled (the
CLI always enables them), the tabs carry no content; the `render_content`
callback returns the selected tab's prepared divs. Only the visible tab's
graphs exist in the browser at any time.

### Callbacks

`setupCallbacks` registers one tab callback and, for every graph id in
`graphList`, the following:

| Callback | Inputs | Output | Behaviour |
|---|---|---|---|
| `apply_ranges` | Apply and Reset `n_clicks` of every graph in the graph's x group | the graph's `figure` | Returns a `Patch` that changes only the axis range, so the trace data is not resent. x applies across the whole `commonX` group; y only to the graph whose own boxes were used. Non-numeric or empty boxes, and start >= end, are ignored. |
| `show_ranges` | the graph's `relayoutData` | its four range inputs | Writes the current axis range back into the boxes after any mouse zoom, pan or autoscale; blank after an autorange. |
| `display_click_data` | the graph's `clickData` | its Click Data box | Non-`commonX` graphs: previous and current `[x, y]` from `customdata`, and their difference. |
| `display_common_click_data` | `clickData` of every graph in the group | its Click Data box | `commonX` graphs: x history and, for each trace, the nearest recorded sample at the clicked x. |
| `display_selected_data`, `display_common_selected_data` | `selectedData` of the graph, or of its whole group | its selection box | The selected x window and, for each trace, its true y extent inside it (enumerations: the states visited). Box and lasso selections are both handled (`selectionBounds`). |

Callbacks that serve a whole group bind the per-graph identity through a
default argument or a `State`, not a closure over the loop variable,
which would be rebound before the callback fires.

`suppress_callback_exceptions` is on, because callback targets exist only
while their tab is displayed.

### Port selection

The Werkzeug server under Dash binds with `SO_REUSEADDR`. On Windows that
option lets a second process bind a port that another server is already
listening on, so two servers would share one port and the browser would
keep reaching the first one.

`freePort` therefore searches upward from the requested port to 65535 and
accepts a candidate only if both tests pass:

1. An exclusive bind to `127.0.0.1` succeeds (`SO_EXCLUSIVEADDRUSE` where
   the platform has it). This rejects ports that are in use, bound but not
   listening, or reserved by the operating system.
1. A connect to the port gets no answer (0.5 s timeout).

The bind test runs first because it fails immediately, whereas on Windows
a refused loopback connect waits for the full timeout; testing connect
first made skipping a reserved range take minutes. Only the CLI calls
`freePort`; `runPlotter` uses whatever port it is given. Two processes
started at the same instant can still pick the same port, because the
port is released between the test and the server's own bind.

## Browser-side behaviour

`assets/graphsync.js` is served automatically from the Dash assets folder
and needs no Python callback. It attaches Plotly event handlers to every
`.js-plotly-plot` element, and a `MutationObserver` re-attaches them
whenever tab content is replaced.

- Hover: a `plotly_hover` on one graph calls `Plotly.Fx.hover` with the
  same `xval` on every other visible graph on the page. Each graph
  resolves that x against its own samples, so nothing is interpolated.
  `plotly_unhover` clears them.
- Shared x range: a `plotly_relayout` that changes the x range (or
  autorange) on a graph inside a `.graph-row.common-x` row is applied with
  `Plotly.relayout` to every other graph in that tab's group. The y axes
  are left alone.
- Echo suppression: driving a graph makes it emit the same event in turn.
  Each graph carries a counter, incremented before it is driven and
  decremented only when that drive has finished; `Plotly.relayout` is
  asynchronous, so the counter is released from its promise. A counter per
  graph, rather than one page-wide flag, means one stuck graph cannot
  disable syncing everywhere.

`density.css` tightens the vertical spacing of the base stylesheet and
lays out the graph row and readout column; the density class on the page
root selects between compact and comfortable rules.

## State and concurrency

Two kinds of state exist.

Module-level globals, set during start-up and read by callbacks:
`dfPlotterHeader`, `dfPlotterConfig`, `pageDensity` (by `loadConfig`);
`divSets`, `graphTabs`, `graphList` (by `prepareGraphs`); `dashApp` (by
`runDash`). One process can therefore hold only one plotter; a second
`DashLinePlot` instance in the same process would overwrite the first
one's state.

Instance attributes on `DashLinePlot`, written by callbacks:
`clickedData` and `clickedX` (click history), plus `graphTraces`,
`graphXAxis` and `commonXGroups`, built during graph construction. Click
history is held by the server, not the browser, so every browser window
open on the same server shares one click history per graph.

Threads: the Dash/Flask server runs in a daemon thread started by
`runPlotter`; the main thread only waits, so Ctrl+C ends the process and
the daemon thread with it. Dash callbacks run on the server's request
threads.

## Error handling

| Condition | Handling |
|---|---|
| Dash not importable | Message on stderr naming the conda environment; exit 1. |
| JSON configuration missing `header` or `sheets` | `ValueError` naming the missing key(s). |
| Data file not found | Message on stdout; `loadData` returns `False`; CLI exits 1 with a hint about `--datadir`. |
| JSON group missing, unexpected, or unknown | `ValueError` listing the groups present. |
| Trace references an unloaded file, or an unknown x or y column | `ValueError` naming sheet, row, and what was available. |
| `Title` without a `yLabel` row | `ValueError` naming the sheet and title. |
| Unrecognised `Density` | Warning; `compact` used. |
| Malformed cells, bad range-box input | Treated as blank; the default applies or the input is ignored. |
| No free port at or above the requested one | `RuntimeError`. |

## Supporting tools

`tools/config_from_run.py <directory> [-o out.json] [-x t] [--height N]
[--density D]` writes a JSON configuration with one tab per data group
(per file for a record array, per group for a multi-rate file) and one
graph per column, with the given column (default `t`) on the x axis.
Text columns are configured as enumerations, not skipped. `manifest.json`
is ignored.

`tools/xlsx_config_to_json.py <workbook> [-o out.json]` converts an
`.xlsx` configuration to the JSON schema `readConfigTables` reads. Empty
cells are omitted rather than written as `null`, since the loader
reinstates missing columns as NaN.

## Dependencies

From `environment.yml` (conda-forge, version floors only): Python 3.13 or
later, Dash 4.4, Plotly 7.0, pandas 3.0, numpy 2.5, openpyxl 3.1. Points
that depend on those versions:

- Dash 4 has `run`, not `run_server`.
- pandas 3 removed positional fallback for `Series[int]`; the code uses
  `.values[0]` or `.iloc[0]` on filtered frames.
- Plotly.js 4 needs axis titles as `{'text': ...}`.

`resourcePath` resolves `assets/` and `icons/` relative to the script, or
to PyInstaller's `_MEIPASS` when frozen; no packaged build is currently
maintained.

## Known design limitations

These are properties of the current design, recorded here so they are
not mistaken for intended behaviour. The backlog and its priorities live
in `suggestedwork.md`.

- Module-level globals limit a process to one plotter (see State and
  concurrency).
- Set and trace numbers are recovered by parsing `Index` labels such as
  `yValue#001-002`, rather than held in their own columns.
- Click history is shared by every browser viewing the same server.
- `suppress_callback_exceptions` is on globally, so a callback whose
  target id is wrong is silently ignored.
- When a sheet has no `ToDisk` row at all, `makeGraphSet` treats export
  as on and writes `./graphs/*.html` on every run; a blank `ToDisk` cell
  means off. TODO: confirm whether "no row" should also mean off; the two
  cases currently disagree.
- Format dispatch tests whether the extension contains `xls` or `json`,
  rather than matching it exactly, and every other extension is read as
  delimited text.
- `freePort` cannot reserve the port it returns; see Port selection.
